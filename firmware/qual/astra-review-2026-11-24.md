# LarkBridge host review, 24 November 2026

Reviewed the S31 gateway and ESP32 output at `f37b566` against the earlier Codex report. Source locations below refer to that revision. A clean native build passed all eight CTest targets after both fixes. The hardware checks below are proposed tests. Target compilation, flashing and D5 belong to the hardware and AEC owners.

## High

1. **An acknowledged route or car key can disappear after hours of normal use.** `firmware/s31/main/link_uart.c:96`, `firmware/output/main/output_control.c:116`, `firmware/common/src/bridge_link.c:52`. Each sender originally advanced one counter for all traffic. Each receiver remembers reliable sequences by type. For example, after route 0 and 32,768 other packets, route 32,769 falls outside both the forward half-range and the 32-packet history. The output skips the update and acknowledges success at `output_control.c:332`. The S31 can complete the silence fence without the output having applied it, then advertise a route that disagrees with the output's stored route. Playback can stay silent. The same test in `link_uart.c:170` silently consumes a fresh AVRCP tap. At three S31 periodic packets every 500 ms this boundary arrives in about 91 minutes. Fixed in `08aeaa7` with per-type counters on both senders. The host regression crosses both the idle gap and the command counter wrap, then repeats the command. On hardware, hold media steady for two hours, take a call and compare both boards' applied routes and PCM taps. Exercise an AVRCP key after enough output telemetry to cross the same boundary and count one action on the phone.

2. **A concurrent PCM write can split a stereo sample across I2S blocks.** `firmware/s31/main/audio_router.c:296`, `firmware/common/src/bridge_ring.c:78`, `firmware/s31/main/audio_router.c:133`. The producer checks space for a complete chunk but originally published each byte separately. At low fill the writer task can see one byte, read it, zero-fill the rest of its DMA block and begin the next block with the second byte. Subsequent frames can have swapped bytes or channels until another discontinuity. Fixed in `780ed88` by copying across the ring boundary and publishing the write index once. The host ring tests cover capacity and FIFO order. To verify scheduling on hardware, stream distinct left/right sample patterns, force repeated near-empty reads, and check the I2S capture for whole stereo frames on both sides of every silence boundary.

## Medium

3. **A dropped USB lifecycle event can strand the receiver.** `firmware/s31/main/uac_lark.c:77`, `:93`, `:160`, `:275`. RX completions and lifecycle callbacks use the same 16-entry queue with zero wait. Losing DISCONNECTED leaves the old handle installed if no subsequent read error closes it. The next connect then cannot open the new device. Losing RX_CONNECTED itself leaves no initial open scheduled. Coalesce data-ready notifications and reserve delivery for lifecycle events, or latch overflow and reconcile the device in the owner task. Count lost events in stats. On the H6 fixture, delay the consumer until the queue fills, detach and reattach, then require a new handle, renewed RX bytes and a truthful ready flag.

4. **A dropped output Bluetooth event can prevent reconnect indefinitely.** `firmware/output/main/output_bluetooth.c:185`, `:310`, `:716`, `:834`. DISCOVERY_STOPPED moves the worker out of discovery. A queue overflow reports a fault but drops that transition. The worker has deadlines for connecting and disconnecting, with none for discovering. A dropped disconnect after qualification can likewise leave connected/streaming flags set after car power loss. Latch overflow outside the queue and make the worker revoke audio and reconcile the stack state. Bound discovery with a deadline. Delay the worker during inquiry until its queue fills, then power-cycle the sink. Verify automatic rediscovery and qualification from both saved-peer and first-pair states.

5. **An incomplete AVRCP tap can block different keys after retry exhaustion.** `firmware/s31/main/bt_gateway.c:594`, `firmware/output/main/output_control.c:370`. If press succeeds and every release submission fails, the output abandons the packet. The S31 still owns a pending release. A different key now returns NOT_READY before sending anything. A later tap of the original key can complete only the old release. Give the S31 responsibility for bounded release recovery, track the originating session/sequence, and clear pending state through an explicit recovery path. Inject release-submit errors through all five attempts while keeping AVRCP connected. Restore submission, press a different key and check the phone's actual press/release sequence.

6. **Release boot can erase saved peers despite the erase option being off.** `firmware/s31/main/app_main.c:61`, `firmware/output/main/app_main.c:55`. Both images erase the entire default NVS partition when init reports NO_FREE_PAGES or NEW_VERSION_FOUND. After an incompatible rollback or exhausted partition, a previously paired installation can return to first-pair behavior. The normal boot banner reports the configured erase option, which cannot explain this recovery erase. Preserve the partition on these errors, report the reason and require an explicit recovery decision. Use disposable NVS fixtures for each error, boot both release images, and compare the partition and peer record before and after. Ordinary ignition cycling alone does not establish either error.

7. **Streaming can pass across a source reset or a long stretch of silence.** `rig/esp/soaks/s31_32ue_streaming.py:49`, `:63`, `:73`, `rig/esp/h2h5.py:366`. If the S31 ends with lower uptime than it started, the source filter discards every interior sample. The negative endpoint interval passes the sub-500 ms exception, and coverage divides by one. With the output continuously connected, sampling can miss the reboot. Independently, one nonzero downstream block per minute satisfies the tap check even while source bytes advance through silence. Reject boot/session changes, verify elapsed board time against host time, and score nonzero output against the known stimulus and its intentional gaps. Replay a run with a source reset late between polls and one with 50 seconds of injected silence per minute. Both should fail even if the endpoint profiles look healthy.

8. **S31 I2S write errors leave the link advertising readiness.** `firmware/s31/main/audio_router.c:153`, `firmware/s31/main/link_uart.c:364`. A failed or short write consumes the source PCM and sleeps 20 ms. The handler logs it but leaves I2S ready, and the S31 STATUS field for I2S errors is hardcoded to zero. The car can lose blocks while the route stays authorized. Count short/failed writes, expose the counter, revoke readiness on persistent failure and restore it only after a successful restart. Force a short write and then sustained timeouts in a test image. Compare STATUS, actual WS/data and the route through recovery.

## Further improvements

- Measure stack high-water marks during H6 churn and simultaneous media/console traffic. The S31 UAC task allocates a 3,840-byte read buffer on its 8,192-byte stack (`firmware/s31/main/uac_lark.c:250`, `:372`). Sample the longest writer and USB service gaps alongside queue overflow counts. Stack size alone does not establish watchdog margin.
- Extend H3 with a same-boot one-way UART outage spanning 32,768 heartbeats. At 2 Hz that is about 4.55 hours. The output timeout preserves its heartbeat replay window (`firmware/output/main/output_control.c:552`), and the repeated HELLO of the same session preserves it too. After such a gap, fresh heartbeats can be rejected until their sequence wraps back into range. Test deliberate re-synchronization with a fresh silence fence before reauthorizing audio.
- In the Pixel uplink harness record which SCO addresses were available. `rig/esp/pixel-harness/src/dev/larkbridge/harness/UplinkRecorder.java:138` accepts either address being empty. In multi-headset qualification, mark endpoint identity unverified when the platform only identifies the device type.

## Follow-up fixes and bench handoff

| Finding | Commit | Result |
| --- | --- | --- |
| 6. NVS erase | `19330a2` | Both targets propagate the NVS initialization error to their existing boot error paths. Only the explicitly configured erase-on-boot path erases the partition. S31 stops initialization on error. Output can report diagnostics with Bluetooth down. |
| 7. Streaming verdict | `322a0db` | The reducer checks each board's uptime against host elapsed time and requires the UART session count to stay constant. It includes interior source samples by host timestamp. The output tap now counts stereo frames with either channel nonzero. Each polling interval requires at least 33,075 such frames per second (75% of 44.1 kHz), allowing for tone zero crossings and loop gaps. Source I2S write errors fail the run. This threshold catches the reported 50 seconds of silence per minute. Shorter dropouts still need a sink recording for continuity scoring. Use matching test images for the new telemetry fields. |
| 8. I2S writes | `7d22636` | The S31 writer owns I2S readiness from the first block onward. A failed or short write increments the console and wire counter and revokes readiness. The task continues writing silence and a full successful write permits the normal route fence to run again. The change leaves driver restart policy for hardware qualification. |

Three recovery decisions remain open for the hardware owner.

- **3. USB lifecycle loss.** The owner calls stop/close while the driver task delivers callbacks carrying device handles. Blocking a driver callback on a full queue risks a circular wait. Coalescing RX notifications requires checking how much data one read drains and whether the driver issues another callback with buffered data outstanding. Use the H6 disconnect-under-load case above to verify drain behavior and handle lifetime through immediate replug before changing queue ownership.
- **4. Bluetooth event loss.** Starting discovery again after a deadline alone leaves the lost-disconnect case unresolved. Recovery must distinguish an active controller connection from a stale worker handle. Exercise a dropped discovery-stop and a dropped disconnect with the car connected, and trace the cancel/disconnect result and subsequent callbacks before choosing a reconciliation path. Blindly clearing the local handle could allow reconnect attempts while the old connection still exists.
- **5. Stranded AVRCP release.** Clearing the pending flag at retry exhaustion can leave the phone processing a held key. An autonomous retry across an AVRCP disconnect can instead deliver a release on a different connection. Capture the Pixel's response to release submission failure, disconnect between press and release, and profile-only reconnect. The recovery test needs to observe the phone's key state and show that the next tap, including one of the same key, yields exactly one action. Host ACK/replay tests alone cannot establish that behavior.

Eight native CTest targets and 37 rig unit tests passed. The added cases exercise the PCM frame counter, sparse audio, counter wrap and a source uptime reset. Target compilation and all physical checks remain with the hardware owner.
