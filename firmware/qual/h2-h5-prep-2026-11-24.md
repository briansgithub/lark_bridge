## Run the gates

Build the test images from a committed checkout using the pinned Docker images.

```sh
python3 firmware/tools/build_firmware.py s31 --image test --no-pull
python3 firmware/tools/build_firmware.py output --image test --no-pull
```

Check the [six-wire harness](harness-wiring.md) before the first powered run. On
the Windows host, run these commands in gate order. H2 flashes each app at
0x10000. The existing partition table and NVS stay in place. Omit `--flash`
when the qualification images are already installed.

```powershell
py rig/esp/hil.py run H2 --s31-port COM3 --output-port COM4 --flash --allow-reset
py rig/esp/hil.py run H3 --s31-port COM3 --output-port COM4 --allow-reset
py rig/esp/hil.py run H4 --s31-port COM3 --output-port COM4 --analyzer fx2lafw
py rig/esp/hil.py run H5 --s31-port COM3 --output-port COM4 --fake-car-address AA:BB:CC:DD:EE:FF
```

Use the real bonded sink address for H5. Omit `--analyzer` for tap-only H4
evidence, whose highest verdict is PARTIAL. The analyzer needs to sample CH0,
CH1 and CH2 at 24 MS/s. The runner records evidence under
`docs/experiments/results/E21`. Replay a result with
`hil.py reduce H4 --log bench.jsonl --log tone.bin --log silence.bin`
using that result's artifact paths. Include an optional fake-car WAV recorded
during the H5 measurement window with `--log` on replay. H5 checks for a 1 kHz
tone in a 100 ms sample at the center of each 30 s recording segment.

## Reuse and thresholds

The Pi reference's `origin/codex/esp32-dual-radio-port` tip `7df8115` is already
in this branch's ancestry. H4 calls `rig/analysis/glitch_detect.py:step` on wire
PCM. H5 uses `rig/analysis/wav_level.py:goertzel` for the optional recording.
The H5 segment scoring follows the pattern in `rig/dropoutctl.py`. The S31
generates the tone so H4 can test each I2S slot and H3/H5 can exercise the real
route and audio gates.

H3 records the measured timeout and currently allows 1,600 ms for the 1,500 ms
policy plus task sampling delay. Brian needs to decide whether to tighten the
firmware and gate to a measured 1,500 ms maximum. A reboot that reestablishes
the link before timeout can prove a new session and recovery. It leaves the
timeout-based audio mute check partial unless the mute was observed. H5 treats
500 ppm as saturation and fails the gate at that value. The optional WAV checks
sampled tone presence. A listener or separate recording analysis can check
glitches until there is a recording glitch threshold for H5.
