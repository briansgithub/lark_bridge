# H2-H5 prep, 2026-11-24

Worktree `lark_bridge-h2h5`, branch `claude/h2-h5-prep`.

## Run the gates

Build the test images from a committed checkout using the pinned Docker images.

```sh
python3 firmware/tools/build_firmware.py s31 --image test --no-pull
python3 firmware/tools/build_firmware.py output --image test --no-pull
```

Check the [six-wire harness](harness-wiring.md) before the first powered run. On
the Windows host, run these commands in gate order. H2 flashes each app at
0x10000. The existing partition table and NVS stay in place. Omit `--flash`
when the qualification images are already installed.

```powershell
py rig/esp/hil.py run H2 --s31-port COM3 --output-port COM4 --flash --allow-reset
py rig/esp/hil.py run H3 --s31-port COM3 --output-port COM4 --allow-reset
py rig/esp/hil.py run H4 --s31-port COM3 --output-port COM4
py rig/esp/hil.py run H5 --s31-port COM3 --output-port COM4 --fake-car-address AA:BB:CC:DD:EE:FF
```

Use the real bonded sink address for H5. Brian confirmed there is no logic
analyzer. For H4, the S31 sends a 1 kHz stereo tone with unequal channel
levels, followed by silence. Check the DevKitC receiver tap for nominal-clock
frequency, per-channel RMS, channel order, advancing frame count, and the
CRC-32 of a zero PCM block. Tap evidence covers decoded PCM. The actual I2S
clock rate, slot width, edge timing and sample-by-sample phase remain unmeasured.
The runner records evidence under `docs/experiments/results/E21`. Replay tap
evidence with `hil.py reduce H4 --log bench.jsonl`. Include an optional H5
recording with `--log` on replay.

| Gate | Evidence |
|---|---|
| H2 | 600 s of UART heartbeats, four frame faults in each direction, one executed route for three copies, and a 30 s clean follow-up |
| H3 | UART TX mute and app reboot on each board, peer timeout and session recovery, output audio state, saved peers before and after |
| H4 | 1 kHz at -20 dBFS with the right channel inverted and halved, 10 s of zero-valued PCM taps, optional direct I2S timing and samples |
| H5 | 60 s warm-up and 1,800 s of FIFO levels and excursions, rate correction, streaming and audio error counters |

## Reuse and thresholds

The Pi reference's `origin/codex/esp32-dual-radio-port` tip `7df8115` is already
in this branch's ancestry. H4 calls `rig/analysis/glitch_detect.py:step` on wire
PCM. H5 uses `rig/analysis/wav_level.py:goertzel` for the optional recording.
The H5 segment scoring follows the pattern in `rig/dropoutctl.py`. The S31
generates the tone so H4 can test each I2S slot and H3/H5 can exercise the real
route and audio gates.

H3 scores the time from the last heartbeat to the observed timeout at a
maximum of 1,500 ms. Both boards use a 1,400 ms policy to leave margin for
UART task scheduling. A reboot that recovers before timeout can prove a
new session. A live sink is needed to verify audio mute and recovery.

H5 uses FIFO minimum, maximum, level, correction, and under/overrun
telemetry. The I2S receiver tap runs without A2DP, but production ring
writes require downstream readiness and its drift controller runs only
on A2DP pulls. An unplugged speaker permits a receiver PCM smoke. It leaves
H5 FIFO drift unmeasured.
