# rpi-lark-bridge endpoint policy note (ADR-0002, AMENDED)
#
# The Mode 1W loopbacks are NOT declared here any more. They are created and destroyed by
# bridge-supervisor (pi/bridged/bridge_supervisor.py) as calls come and go.
#
# WHY THE DECLARATIVE VERSION WAS WITHDRAWN
# -----------------------------------------
# ADR-0002 assumed endpoints are persistent. The HFP nodes are not: bluez_input/
# bluez_output for the phone exist ONLY while SCO is up, i.e. during a call.
#
# Measured: WirePlumber does not leave a stream waiting when target.object is absent —
# it links it to the DEFAULT device. With no call active that gave
#     bridge.mic.playback    -> dongle B   (wanted: HFP sink)
#     bridge.callout.capture -> Lark       (wanted: HFP source)
# closing Lark -> callout.playback -> car speakers -> Lark: a live acoustic feedback loop.
#
# The supervisor removes the failure by construction: no target, no loopback, nothing to
# fall back to. ADR-0002's core claim still holds for PERSISTENT endpoints; it simply does
# not extend to transient ones.
#
# This file deliberately uses a .txt suffix so PipeWire never parses it as configuration.
